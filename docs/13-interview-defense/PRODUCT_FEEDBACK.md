# FDE field-to-product feedback template

Finding ID, customer type (anonymized), workflow, repeat frequency, business impact, reproduction fixture, expected vs actual result, root cause hypothesis, short-term workaround, proposed core-product change, API compatibility/security implications, implementation owner, customer communication, measured post-release improvement.

Example: ambiguous alias matching is reproduced for multiple fictional customer tenants. The FDE files a generalized request for match evidence and uncertainty metadata rather than bespoke per-customer thresholds.
